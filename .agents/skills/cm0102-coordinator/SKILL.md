# Coordinate CM 01/02 recovery

Bulk MiniMax/DeepSeek translation runs through `docs/agent/FARM.md`, which needs no worktrees or coordinator. Use this skill only for by-hand isolated worktree workers.

Use `F:/src/cm0102-decompiled` as the sole coordinator. Read its `AGENTS.md`, `docs/agent/PLAYBOOK.md`, `docs/agent/WORKTREES.md` and the relevant C or campaign workflow. The coordinator owns the local binary, evidence, claims, failure history and ledger; only `cmre accept` establishes recovery. Game files and analysis stay local.

1. Inspect the current handoff and coordinator preflight and validation receipts. If a required revalidation is live, wait on that process; resolve failed or incomplete required coverage before recovery. Start `py -3.13 scripts/cmre_session.py start` once per parent session and require a finished green preflight. Workers inherit its receipt. Reuse matching evidence; do not launch whole-inventory revalidation merely for a new session or skill change. Preserve existing work and active claims.
2. Bootstrap each authorized ad hoc worker from the coordinator; use `cmre worktree bootstrap WORKER --align` for a fresh unbound tree whose tooling differs. Follow `docs/agent/WORKTREES.md` for protected edits, stale bindings and retry. Select an eligible lifted function without accepted C, no larger than 600 inventory bytes, using `cmre next --c --max-bytes 600`, respecting assigned shard or subsystem. Screen its complete original C corpus with `cmre screen fn_X` before dispatch; no observed return means retain an evidence obligation and select independent work. A return remains a scheduling signal, never acceptance. Claim each function with `cmre worktree claim WORKER fn_X --owner UNIQUE_OWNER --seconds 3600`. Claims are atomic; select another function if one is already held. Avoid pre-claiming with `cmre next --claim`.
3. Check the ABI and required raw alias/fault evidence before assigning a likely register/stack adapter; follow `WORKTREES.md` if witnesses are unavailable. Assign workers their isolated paths, function IDs, packet locations and inherited preflight receipt. Workers edit their own C and run `cmre worktree test fn_X`; coordinator testing can occur concurrently for disjoint functions. Keep harness and build inputs fixed. Workers report pass or WIP with source/report hashes. Do not create worktrees or spawn agents unless authorized by the user.
4. Obtain an independent evidence review for each passing candidate. Record it with `cmre worktree review` using the actual source and report hashes, then run `cmre worktree publish` serially at the coordinator. Here publish means local acceptance, not a remote push. Preserve failed attempts and the five-attempt ceiling. Larger functions and machine batches stay in the coordinator's normal workflow; never accept from a worker.
5. Run `py -3.13 scripts/cmre_session.py check` at the parent boundary. Report passed and held functions, accepted C/legacy bytes, lift-inclusive recovery, composed calls and live integration separately. Track accepted bytes and review costs before increasing concurrency. Never push or remotely publish game files or analysis.
